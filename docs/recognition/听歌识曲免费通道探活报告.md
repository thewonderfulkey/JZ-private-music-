# 听歌识曲免费通道探活报告

调查对象：JZ 音乐助手（`com.jz.musichelper`）识曲链路
调查目标：在**全部免费通道**（不接 ACRCloud / AudD / 腾讯 mediax 等付费服务）里，找出可以接的第二通道
调查时间：2026-10-28
结论口径：每条通道都标注「实测过 / 只读代码未实测 / 不可用」，不含推测口径

---

## 0. 一句话结论

GitHub 上真正能跑通的免费识曲通道只有三条，且都受同一个瓶颈约束——**指纹必须本地生成**：

| # | 通道 | 免费 | 实测状态 | 端上最大障碍 |
|---|---|---|---|---|
| 1 | 酷狗 `fingerprint.service`（现用） | 是 | **实测通** | 只吃 8k 裸 PCM，候选恒 5 条，无第二条同族通道 |
| 2 | Shazam 非官方 `amp.shazam.com/discovery/v5` | 是（无 key） | **实测通**（真识别成功） | 需 Rust/C++ 本地指纹 + NDK 工具链；返回英文/罗马化元数据 |
| 3 | 网易 `interface.music.163.com/api/music/audio/match` | 是（无 key） | 接口通、端到端**未完成** | 必须跑网易自家 `afp.wasm`（600 KB），要求 12 s / 48 kHz |

被排除的：ACRCloud、AudD、腾讯智能音乐 mediax（付费/需 key）；AcoustID（需免费 key 且中文曲库弱，实测无 key 直接 400）；网易歌词反查 `type=1006`（已加密）。

## 2. 逐通道实测

### 2.1 酷狗 `fingerprint.service`（现用，实测通）

- 端点：`https://gateway.kugou.com/fingerprint.service/v1/music_trackid_mulit`，`POST` 8k 单声道 16 bit 裸 PCM，签名 `md5(salt + 排序k=v串 + body + salt)`，返回恒 5 条候选。
- 同族通道扫描（本次二次确认，无新增能力）：

| 试法 | 结果 |
|---|---|
| `v2/music_trackid_mulit` | 200 / 5 条，**结果与 v1 完全一致**（同后端，并联无收益） |
| `v1/music_trackid`、`v3/...` | 404 |
| appid/clientver 换 `1005/1005`、`1005/11430` | `error_code=20006`（被拒） |
| host 换 `fp` / `trackid` / `fingerprint` / `fp.service.kugou.com` | DNS 全部不解析 |
| `multi_result` = 1/2/3/5 | 恒回 5 条（参数无效） |
| 直接送 mp3 片段 | `data` 为空（只吃 8k 裸 PCM） |

- 召回实测（《晴天》）：

| 条件 | 结果 |
|---|---|
| 2/3/5/8/10/15/20 s | 全部命中「晴天 / 周杰伦」，首条稳定 |
| 20 s 内 0 s / 7 s / 14 s 三起点 | 全部命中，结论一致 |
| SNR 20 / 10 / 5 / 0 dB | 全部命中 |
| **SNR −5 dB** | **3 s 空、6 s 命中、10 s 空**（同一首歌不同时长结果不一致 → 抖动，靠多段投票提稳定） |
| 候选质量 | 混入翻唱（零のRoy、凌霄、周杰伦小公举、迷茫的吉他、陈满满），需靠现有 `Judge` 过滤 |

结论：酷狗侧已无第二条独立通道可并联，剩余收益只有「多段采样投票」。

### 2.2 Shazam 非官方通道（实测通，本次最大增量）

- 指纹 → 请求链路（以 Audile 的 Kotlin 实现为准，Python 侧同源）：
  - `POST https://amp.shazam.com/discovery/v5/en/US/android/-/tag/{UUID大写}/{UUID}?sync=true&webv3=true&sampling=true&connected=&shazamapiversion=v3&sharehub=true&video=v3`
  - body：`{geolocation, signature:{samplems,timestamp,uri}, timestamp, timezone}`，`uri` 形如 `data:audio/vnd.shazam.sig;base64,…`
  - 请求头只需随机 Android Dalvik UA + `Content-Language: en_US`，**不需要任何 key / token / 登录**
- 实测（`kuwo_51685512_320k.mp3`，40 s 起 10 s，转 44.1 k 单声道）：

| 测试 | 结果 |
|---|---|
| 10 s 40 s 处 | **`Sunny Day (Live)` / `Jay Chou` / 专辑 `Jay Incomparable Concert Live 2004 (Live)`** |
| 3 s | **误报**：`Nothing's gonna stop us now (Español New Version)` / `Melodyne Mld` |
| 5 s / 8 s / 10 s | 均正确 `Sunny Day (Live)` / `Jay Chou` |
| SNR 20 / 10 / 5 / **0 dB** | 全部正确（抗噪比酷狗强；酷狗 −5 dB 已抖） |
| 起点 0 s / 80 s | 正确 |
| 起点 200 s | 未识别 |
| 直连 `amp.shazam.com`（绕开 shazamio 封装） | **HTTP 200，matches=1**（无 key 确认） |

端上含义：
1. 指纹必须本地算（`shazamio` 靠 Rust 的 `shazamio-core`；Android 侧对应 Audile 的 `songrecfp` JNI `.so`，或 vibra 的 C ABI）。
2. **返回英文/罗马化元数据**——《晴天》识别成 `Sunny Day`。对我们「拿中文歌名去酷我/QQ 检索」的链路是硬伤，直接接入会大量错配。
3. 3 s 会误报且误报得很自信，最短时长必须 ≥5 s。

### 2.3 网易 `audio/match`（接口通，端到端未完成）

- 端点与参数（来自 `aplayer-custom` 的 `SongRecognizer.kt`，且本次实测复核）：

```
POST https://interface.music.163.com/api/music/audio/match
Content-Type: application/x-www-form-urlencoded
sessionId=441df692-afea-4a54-8aff-f5f20fd34f12   ← 官方浏览器扩展的固定值，随机 session 会被判 noMatchReason=10
algorithmCode=shazam_v2
duration=12
rawdata=<指纹 base64>
times=2
decrypt=1
```

- 实测（本机 Python 直连）：

| 试法 | 结果 |
|---|---|
| 空/无效 `rawdata=AAAA`，带 `origin: chrome-extension://pgphbbekcgpfaekhcbjamjjkegcclhhd` | HTTP 200，`code:200`，`noMatchReason:10` |
| 同上，**不带 origin** | HTTP 200，同样 `noMatchReason:10` → **origin 不是必需，接口处于开放状态** |
| 用 Shazam 原生签名（`data:audio/vnd.shazam.sig;base64` 部分）充当 `rawdata` | 仍 `noMatchReason:10` → **格式不兼容，网易不认 Shazam 签名** |

- 指纹引擎（`aplayer-custom` 的结论 + 本次资产核查）：

| 项 | 事实 |
|---|---|
| 引擎 | 网易客户端的 `afp.wasm`，裸 JNI 跑不起来（27 个 embind import 无等价实现），只能跑浏览器版 |
| 资产体积 | `afp.wasm` 231,182 B + `afp_wasm_b64.js` 308,272 B + `sandbox.bundle.js` 89,115 B ≈ **629 KB** |
| 调用方式 | WebView 加载 `recognizer.html`，`evaluateJavascript("window.__encode('<pcmBase64>')")` → `AndroidBridge.onResult` 拿指纹 |
| 音频口径 | 48 kHz 单声道录 12 s → 6:1 抽取成 8 kHz Float32 PCM；**喂 8 s 直接 `noMatchReason=10`** |
| 就绪判定 | 需轮询 `processor.start()` 出现 `ExtractQueryFP`（首次约 300–800 ms） |
| 返回内容 | `data.result[].song`：中文歌名、artists、album（含 picUrl）、duration(ms)、网易 songId |

- 未完成项（诚实标注）：本机**没有 Chrome/Edge 任何浏览器运行时**，`mini-racer`（V8）跑这套 wasm 只到「`__NCM__` 载入成功、`processor` 未就绪、Promise 永不 resolve」，因此**没有拿到一条真实指纹去打网易**。接口侧证据（200 / 参数语义 / 资产体积 / 音频口径）齐全，但「真指纹能否出歌」属未验证。

## 3. 端上落地三种形态

| 形态 | 新增体积 | 需要的工具链 | 许可风险 | 元数据语言 | 实测背书 |
|---|---|---|---|---|---|
| **A. 酷狗现状 + 多段投票** | 0 | 无 | 无 | 中文 | 全链路已上线（v2.1.90） |
| **B. 网易 WebView + afp.wasm** | ≈ 629 KB assets | **不需要 NDK/Rust**，只要 assets + 一个 WebView | 捆绑网易私有 wasm（无授权、无 SLA，可能被_version 变更打死） | **中文原生**（歌名/歌手/专辑/songId） | 接口 + 参数 + 体积已实测；端到端未测 |

## 4. 为什么「单接 Shazam」不足以解决问题

- 《晴天》在 Shazam 里是 `Sunny Day (Live)`，且**把现场版识别成带 `(Live)` 的专辑名**——这恰好会放大我们 v2.1.90 刚修完的「原唱 / 其他版本」判定问题：英文变体名进不了现有 `VARIANT_TITLE` 正则，`Judge` 会把它当原唱候选。
- 我们的下行链路是「拿歌名去酷我/QQ 检索」。英文名检索中文曲库命中率不可控，还要额外加罗马化→中文映射。
- 网易通道返回的就是中文 `name/artists/album/duration/songId`，与现有检索链路零改造对接——这也是它尽管有合规风险仍值得优先评估的原因。

## 5. 未验证项 / 缺口清单（不粉饰）

1. **网易端到端未完成**：本机无浏览器运行时，V8 沙箱跑不通完整 wasm 链，未取得真实指纹，未验证「真指纹 → 出歌」。
2. **真机未测**：`adb devices` 恒空，无设备无 AVD；所有结论为桌面侧接口实测，端上表现（48 kHz 录音、WebView 首次编译耗时、内存）未验证。
3. **Shazam 限流未测**：Audile 代码里 429 有专门分支，说明存在配额；批量/长时间压测未做。
4. **网易 `sessionId` 稳定性未测**：该固定值来自官方扩展，是否长期有效、是否与 UA/origin 绑定未验证。
5. **许可未落地**：`aplayer-custom`、Audile、vibra、SongRec 均 GPL-3.0；网易 `afp.wasm` 为第三方私有产物，属「能用但无授权」状态。

## 6. 建议（按投入产出排序）

**第 1 步（0 成本，建议立刻做）**：酷狗通道加「多段采样投票（2–3 个 6 s 片段，按候选交集/投票定首条）」+ 歌词反查兜底。依据：−5 dB 时 3 s 空 / 6 s 命中 / 10 s 空，是同一首歌不同时长的抖动，多段投票是唯一零成本解法；歌词反查（酷我 `r.s`）首条即原唱已验证。

**第 2 步（若确实要加第二条通道）**：走**形态 B（网易 WebView）**——中文元数据、不需要 NDK、体积仅 629 KB，且我们已有 WebView + `evaluateJavascript` 的现成模式。前置动作：先在真机（或装一台模拟器）验证「48 kHz 12 s → 指纹 → 出歌」，验证通过再谈是否入包。

**不建议先做**：形态 C（Shazam + NDK）。理由：GPL-3.0 传染、需要 1–2 GB 工具链、返回英文元数据放大现有变体判定问题，收益低于 B。

**若两条都否**：保持单通道 + 多段投票，接受「酷狗没收录的歌识不出」这一既定上限——本次普查没有找到第四条免费通道。

## 7. 需要你拍板的三件事

1. 是否接受**捆绑网易 `afp.wasm`**（629 KB 私有资产）——这是形态 B 的合规前提。
2. 是否接受 **GPL-3.0 组件**（只有在选形态 C 时才需要回答）。
3. 先做「多段投票」（今天可上），还是直接投入「网易通道」（需先补真机验证）。
