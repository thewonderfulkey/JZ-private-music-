# 下载音质：从"我要无损"到"存下来的到底是什么"

> 最后更新：2026-11-19（r120）. 适用于 iOS（`ios/JZMusicHelper`）与 Android（`android/`）——
> 两端的取流后端、判定口径、换源顺序是同一套，改一边要同步另一边。

## 1. 一句话口径（老板定的）

> **要无损就先把所有接口的无损找一遍，全都没有才降级；要 320k 就先找 320k，全都没有再降/升；
> 128k 同理。优先最精准匹配，否则从最高音质逐级往下取。**

落到代码里就是三步：**先求「正好是目标档」的源（exact），求不到才取「能拿到的最高档」（fallback）**。

## 2. 一次下载的音源解析链

```
点「下载」选档
   │
   ├─ ① 本平台后端（SourceRegistry.adapters(for: song)，按歌曲所在平台）
   │      QQ：cyapi        → 固定 ~97kbps m4a（永远出不了 320k/无损）
   │      网易：gdstudio   → br=740 给真 fLaC（≈1087kbps），br=320/128 也给真档
   │            oiapi      → 三档返回同一条 128k mp3（实测，只作兜底）
   │      酷我：妖狐       → 常给 fLaC（搜索式取流，慢 2~4s）
   │      酷狗：playInfo   → 多为 mp3
   │
   ├─ ② 跨源补源（SameSongCrossResolver.resolveForDownload）
   │      用「歌名 + 歌手」把四个平台都搜一遍 → 过滤同曲（歌名/歌手/时长/版本类）
   │      **排序 = 能出目标档的平台优先**：无损 网易 → 酷我 → 酷狗 → QQ；320k/128k 网易优先
   │      候选分批（每批 3 条）并发解析，整轮 40s 硬超时
   │
   └─ ③ 通用兜底（妖狐酷我，与歌曲来自哪个平台无关）
          无损档：照打（妖狐恒给无损）
          320k/128k：只在"一条源都没有"时才打，否则白等一次超时
```

## 3. 档位怎么判（只信实测，不信接口自报）

一次 `Range: bytes=0-4095` 的请求同时拿两件事：**容器头 16 字节** + **总字节数**。

| 判定 | 规则 |
|---|---|
| 无损 | 容器是 `fLaC`/`RIFF(WAV)`；**或**码率 ≥ 601kbps（容器头被 CDN 改过/前面挂了 ID3 标签时靠这条兜住） |
| 高品 320k | 非无损容器且码率在 256–600 |
| 标准 128k | 非无损容器且码率在 48–255 |
| 算不出码率（0） | 一律不算命中，交给上层决定要不要降级 |

两个实现细节（都是 r120 事故的直接产物）：

1. **容器特征串在头 16 字节里任意位置找**——126.net 的部分 fLaC 前面挂了一段 ID3v2，
   `fLaC` 不在偏移 0；只看偏移 0 会把真无损判成 mp3。
2. **`QualityFacts.of()`（显示成哪一档）与 `matches()`（算不算命中）共用同一组门槛**
   （601 / 256–600 / 48–255）——以前两边各说各话，会出现"命中无损、界面显示 320k"。

下载落盘后会再用**文件本身**复核一次（`DownloadGuard.verdict`）：按文件头 + 体积重算档位，
扩展名以实测容器为准（`.flac` 里装 mp3 会改回 `.mp3`），实测低于所选档时在下载行里写一句人话。

## 4. 降级/升级的取法

- `exact`：所有"算命中目标档"的源，按「同平台优先 → 直连优先 → 码率高的优先」取前 3 条，
  首次命中直接开下（不再要求点第二次）。
- `fallback`：没有 exact 时，取**档位最高**的一条（无损 > 320k > 128k；同档比码率）。
  例：要 128k 但只拿得到无损 → 给无损并写明"没有标准 128k，最高可得无损 FLAC"；
  要无损但只拿得到 128k → 给 128k 并写明"没有无损 FLAC，最高可得标准 128k（本平台 1 条… · 跨源试 8 条全落空）"。

## 5. 事故记录：r120《연애의 조건》（BESTie）

- 现象：安卓能下网易无损（26MB `.flac`），iOS 弹层写"没有无损 FLAC，最高可得标准 128k"，来源 QQ · cyapi · 97kbps。
- 根因（两条）：
  1. `sniffHead` 只认偏移 0 的 `fLaC`，而这条 126.net 直链前面有 ID3v2 → 判成 unknown/mp3 → 档位掉到 320k；
     同时 `matches(.lossless)` 还认码率 ≥600，于是"命中"与"标注"打架。
  2. 下载换源的候选排序里，无损档按「同平台优先」→ QQ 三条 128k 先解析，网易真无损排在后面，
     真机预算一紧就"还没轮到就收工"。
- 修法：容器串任意偏移识别 + of/matches 统一门槛 + 下载换源平台优先（网易/酷我先）+ Range 探测重试一次
  + 降级提示带各阶段实况（本平台几条 / 跨源试几条 / 妖狐结果）。
- 实测（本机真实网络，改后）：6s 内拿到 3 条网易无损（1087~1095kbps，26MB），`fallback` 为空。
