# 桌面歌词（悬浮歌词栏）· 实现方案

目标：点「设置」或播放页右上角三个小点里的「桌面歌词」，App 退到桌面/切到别的应用后，屏幕上仍有一栏歌词跟着播放滚动。

版本口径：若要落地，这一版是 `versionCode 132` / `versionName "2.1.74"`，同步「设置-关于」的版本与「本版更新」。

---

## 一、先说结论

一句话：**用 `WindowManager` 加一层 `TYPE_APPLICATION_OVERLAY` 悬浮窗，宿主挂在已有的 `PlayerService`（前台服务）上；歌词由一个新增的 `DesktopLyrics` 单例负责取词、定位、驱动重绘；窗口内部用原生自绘 View 画，不进 Compose。**

不做什么（避免范围膨胀）：不做逐字卡拉 OK 高亮（KRC 时间轴已有整行，逐字需要另一套词库）、不做锁屏歌词、不做桌面小组件（AppWidget 无法逐行滚动）。

## 三、为什么是「悬浮窗 + 原生自绘 View」

三条路线里，这一条是唯一能满足「桌面也能滚动」且有可控视觉的：

| 路线 | 能不能做 | 结论 |
| --- | --- | --- |
| **悬浮窗（SYSTEM_ALERT_WINDOW）** | 能，且能盖在所有应用之上；26+ 用 `TYPE_APPLICATION_OVERLAY` | **采用** |
| 通知栏歌词（MediaStyle 自定义 RemoteViews） | 只能放通知区，Android 原生通知的布局能力极有限，逐行滚动动画做不出来 | 不做 |
| 桌面小组件（AppWidget） | 刷新靠 `RemoteViews`/`AppWidget` 周期，秒级逐行滚动必然抖 | 不做 |
| 悬浮窗里塞 ComposeView | 能跑，但 ComposeView 在窗口里必须自己注入 `ViewTreeLifecycleOwner`/`SavedStateRegistryOwner`，否则崩；且重绘要跟着自己的帧时钟走 | 不做（见下） |

窗口内部选择**原生 `View` 自绘**的理由（很实际）：

1. 没有 ViewTree 生命周期依赖，`WindowManager.addView(view, params)` 即插即用，不会因为 App 界面销毁而崩。
2. 换行动画用 `ValueAnimator`（300ms）自己控，不需要 Compose 的组合时钟，后台也不会卡顿。
3. 内存和耗电低：只有一个窗口、一个 View、一个 200ms 的重绘循环（只在播放时跑）。
4. 视觉可控：水墨两行、行间交叉淡出、当前行描重，全部自己算。

## 四、要动 / 新增的文件（先不动代码，这里只列清单）

### 新增

**1. `data/DesktopLyrics.kt`（核心，约 300 行）**

单例，负责状态与窗口生命周期：

```
object DesktopLyrics {
    val enabled: MutableStateFlow<Boolean>        // 开关（持久化 jz_music_prefs）
    val canOverlay: MutableStateFlow<Boolean>     // Settings.canDrawOverlays
    fun init(ctx: Context)                        // 应用启动时调用，读偏好
    fun setEnabled(ctx: Context, on: Boolean)     // 开：先查权限；未授权 → 抛 needPermission 事件
    fun show(ctx: Context) / hide()
    fun onSongChanged(song: Song?)                // 切歌：清行、发起 fetch(song)、加载态
    fun onTick()                                  // 200ms：算 index、推给 View
}
```

内部还要做三件事：
- 监听 `AppState.lastSong`（切歌）与 `PlayerManager.isPlaying`（暂停/续播）；
- 自己起一个 `Handler` 的 200ms 循环（**只在播放中跑**，暂停即停，避免空转耗电）；
- 记住用户拖到的位置（`x/y` 存 prefs，转屏后按比例复位）。

**2. `ui/DesktopLyricsView.kt`（自绘，约 220 行）**

一个 `View`，`onDraw` 里画：
- 圆角纸底（`#F2FAF8F3` 85%），1dp 墨线描边（`#DED7C8`），圆角 18dp；
- 当前行（15sp，`#2E2A24`，字距 0.5sp）+ 下一行（13sp，`#8A8378`）；
- 换行时：旧行向上 10dp 淡出（alpha 0.85→0）、新行从下 10dp 淡入，300ms `ValueAnimator`；
- 暂停时：当前行右侧画一个 10dp 的「‖」暂停符号，透明度降到 0.6（而不是整窗消失，避免"眨眼"）；
- 无词/加载中：单行居中显示「歌词加载中…」或「暂无歌词」。

触摸：`onTouchEvent` 接收 `ACTION_DOWN/MOVE` → 更新 `LayoutParams.x/y`（`FLAG_NOT_FOCUSABLE` 保证不抢输入法焦点），松手吸附左右边距 ≥16dp 并把位置写 prefs。

### 改动

**3. `AndroidManifest.xml`**：加一行
```xml
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
```
`PlayerService` 的 `foregroundServiceType="mediaPlayback"` 不动——悬浮窗不需要新的服务类型。

**4. `data/PlayerManager.kt`**：加一个直读方法（约 5 行）
```kotlin
fun currentPositionMs(): Long = runCatching { player?.currentPosition?.toLong() }.getOrNull() ?: _position.value
```
理由：500ms 的 ticker 粒度会让换行最多晚半拍，桌面歌词对这一点很敏感。

**5. `MainActivity.kt`**：`onCreate` 里加 `DesktopLyrics.init(this)`；`onResume` 里复查 `canDrawOverlays`（用户从系统设置页返回后要立刻反映）。

**6. `ui/PlayerScreen.kt:851 PlayerTopBar`**：把假按钮换成真菜单。

```
IconButtonCompat(Icons.Filled.MoreVert, "更多") → Box {
    IconButtonCompatOnClick { menuOpen = true }
    DropdownMenu(expanded = menuOpen, onDismissRequest = { menuOpen = false }) {
        item("桌面歌词" + (if (enabled) " · 已开" else ""))  // 点击 → DesktopLyrics.setEnabled
        item("查看歌词 / 封面")                              // 复用已有 onToggleLyrics（双击同款）
    }
}
```
只放这两项，不趁机塞别的操作（范围控制）。菜单样式跟水墨口径：纸底、墨字、选中项前缀一个朱砂点。

**7. `ui/SettingsScreen.kt`**：在「后台连播」段落前插一段「桌面歌词」：

```
桌面歌词                                  [ 开关 ]
在桌面和其他应用之上显示滚动歌词
状态：已授权 / 未授权（点击去授权）
位置：拖动歌词栏可调整，松手吸附边距        [重置位置]
```

- 开关打开且未授权 → 弹一个水墨对话框解释「需要在系统设置里允许"显示在其他应用上层"」，再跳系统页；返回后未授权则开关自动回弹并提示；
- 未授权状态下这一行显示「去授权」入口，点它直接跳系统设置（不改开关）。

**8. `SettingsScreen.kt` 关于页 + `build.gradle.kts`**：版本 bump 到 `2.1.74` / `132`，「本版更新」换成桌面歌词说明（一句话讲清入口与能力，不写营销话）。

## 五、数据流（一句话版本）

```
点击某首歌
  → AppState.lastSong = song                              （已有）
  → LyricsService.fetch(song) 全局预取                     （已有，App.kt:320）
  → DesktopLyrics.onSongChanged(song)：清行 → 加载态 → 等 fetch 结果
播放中（每 200ms）
  → PlayerManager.currentPositionMs()
  → LyricsService.indexAt(lines, pos)                      （已有函数，与播放页同一口径）
  → index 变化 → DesktopLyricsView 触发 300ms 换行动画
暂停 / 停止 / 退出
  → 循环停跑，窗口留最后一帧（暂停态）
```

关键点：**歌词不在悬浮窗里另起一套解析**，全部复用 `LyricsService`（同一份 4h 缓存 + in-flight 去重），所以悬浮窗和播放页不会出现"两处歌词不一样"。

## 六、权限与降级（这是这个功能最容易翻车的地方）

1. **判定**：`Settings.canDrawOverlays(context)`。
2. **申请**：`Intent(Settings.ACTION_MANAGE_OVERLAY_PERMISSION, Uri.parse("package:$packageName"))`，必须由用户在 App 前台点击触发（Android 14 不许后台起 Activity）。
3. **返回复查**：`MainActivity.onResume` 读一次权限，把状态推给设置页与菜单项；授权了就自动把窗口弹出来（用户点了开关但没授权时，授权回来要"接上"）。
4. **国产 ROM 兜底**：`ACTION_MANAGE_OVERLAY_PERMISSION` 打不开时（部分 MIUI/EMUI 会抛 `ActivityNotFoundException`），退到 `ACTION_APPLICATION_DETAILS_SETTINGS`，并在文案里写清楚「去『权限管理』里找『显示悬浮窗/在其他应用上层显示』」。
5. **彻底拒绝**：开关回弹 + toast「未获得悬浮窗权限，桌面歌词不会显示」；不写"请去设置开启"这种空话。
6. **通知权限**（`POST_NOTIFICATIONS`，33+）与悬浮窗是两件事，不要混。已有逻辑不动。

## 七、视觉规格（沿用纸色水墨，不引入新风格）

窗口：宽 = `min(屏宽 - 32dp, 480dp)`，高 = 两行 88dp（单行 52dp），默认落位：底部往上 120dp 居中。

| 元素 | 规格 |
| --- | --- |
| 底 | 圆角 18dp，`#F2FAF8F3`（85% 不透明的纸白），1dp 描边 `#DED7C8` |
| 当前行 | 霞鹜文楷 15sp，`#2E2A24`，字距 0.5sp，单行省略（`TextUtils.TruncateAt.END`） |
| 下一行 | 同字体 13sp，`#8A8378`，alpha 0.75 |
| 换行 | 300ms，旧行上移 10dp + 淡出，新行下移 10dp + 淡入，`DecelerateInterpolator` |
| 暂停态 | 当前行 α0.6 + 右侧「‖」10dp 墨点符号 |
| 空态 | 居中 13sp `#8A8378`：`歌词加载中…` / `暂无歌词` |
| 阴影 | 无（水墨不用投影），靠描边与纸底区分层次 |

不做毛玻璃、不做 neon、不做渐变大色块——与「俗/low」的红线保持一致。

## 八、需要你拍板的 4 件事（默认值已给出，不改也可以）

1. **几行**：默认**两行**（当前 + 下一行），与主流桌面歌词一致；单行更干净但信息少。
2. **App 内播放页打开时是否也显示**：默认**自动隐藏**（避免和播放页自己的歌词区打架、遮住封面下半），回到桌面/切到别的 App 才出现。若你希望"任何时候都在最上层"，改成常显。
3. **暂停时**：默认**保留最后一帧变灰**（不消失）；另一种是暂停即隐藏。
4. **默认位置**：默认**底部居中偏上 120dp、可拖动、松手吸边**；另一种是固定顶部不可拖。

## 九、验证计划（这个功能静态验证覆盖不到，必须说清）

- **静态**（apk-verify 可做）：`SYSTEM_ALERT_WINDOW` 权限出现在 badging 列表、`PlayerService` 组件声明不变、签名与 zip 完整性、版本三方一致（gradle / badging / 关于页）。
- **动态（必须真机）**：本机 `adb devices` 长期为空，所以
  - 悬浮窗能否在桌面出现、能否盖在其他 App 上；
  - 歌词是否跟随播放滚动、切歌是否重载、暂停/续播是否正确；
  - 拖动位置在转屏后是否仍然合理；
  - 授权回来后开关是否自动接上。
  这四条**只能靠你在真机上点一遍**，我会在交付说明里写成缺口，不会用"静态通过"糊过去。

## 十、风险清单（提前写，避免做完才发现）

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| 国产 ROM 默认关悬浮窗 | MIUI/EMUI/ColorOS 常把"后台弹出界面""显示悬浮窗"拆成多个开关 | 设置页显示实时状态 + 双入口（悬浮窗页 / 应用详情页） |
| 悬浮窗与系统手势条/输入法重叠 | 默认落在底部 120dp，输入法弹出时会躲不开键盘 | 监听 `WindowInsets`/`Configuration`，键盘弹出时窗口上移 |
| 息屏时窗口是否还在 | 息屏后系统可能暂停绘制 | 接受"息屏不显示"，这不算缺陷；播放页方案里已有 `SCREEN_ON` 兜底 |
| 耗电 | 200ms 重绘 + 只在前台服务存活期间 | 暂停/停止即停循环；窗口不可见时也停 |
| 歌词为空 | LDDC 对冷门曲目会 return null | 空态文案明确，不显示假歌词 |
| 多行歌词超长 | 单行过长会被裁 | 单行省略 + 可选"过长自动缩小一号字" |

## 十一、工作量与顺序（落码时按这个顺序，能尽早暴露问题）

1. `DesktopLyrics` 骨架 + `DesktopLyricsView` 自绘（先写死一句假歌词，把窗口调出来）——**这一步就能验证权限、位置、绘制**；
2. 接 `AppState.lastSong` + `LyricsService` + `currentPositionMs`，跑通滚动与切歌；
3. 接两个入口（三点菜单 / 设置页）+ 持久化 + 权限往返；
4. 视觉收尾（换行动画、暂停态、空态、吸边）；
5. 版本 bump + 关于页 + 构建 + `apk-verify` 静态 + 真机清单交给你复核。

1→2 之间一定要先看窗口能不能出来，否则后面的滚动逻辑全是白搭。
