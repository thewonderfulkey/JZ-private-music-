# 笒音 2.0.1（com.cenmusic.app）逆向：音乐 / 封面 / 歌词 API 对照

> 取证对象：开发群 2026-11-12 00:46 周亚楠发的 `base.apk`（`file_v3_0017b_7d1a3d77-04bb-49d2-b75c-8f0330b1745g`，195,019,234 B）。
> 本文只列接口事实与对照结论，不含可直接复用的取流实现。

---

## 0. 一句话结论

这个包**没有壳**，是纯 Flutter AOT 应用，业务逻辑全在 `libapp.so`（Dart 快照）里；
它的在线音乐只用了**酷我一条源**，走的是「酷我移动端聚合入口 + 酷我 web openapi」两套；
对照我们的 `network/` 层，**我们没有的是：酷我歌词、酷我官方取流、酷我封面三形态、推荐流、歌单/专辑/榜单/评论/联想词/MV 这几组只读接口，以及 mflac/mgg 本地解密能力**。

**「有壳就砸壳」这一条不适用**：既没有加固壳，也没有 dex 整体加密或 VMP。dex 里只有 Flutter 插件（just_audio、audio_service、video_player、Tika、DataStore 等），

所以「砸壳」这个动作对本案没有意义，能做的只有静态提取字符串 + 端点探活。

### 1.1 与取流/解密相关的原生入口（实证）

- `libcenbridge.so`：`Java_com_cenmusic_app_Mflac_init`(0x1a920)、`_decrypt`(0x1aacc)、`_release`(0x1adc4)
- `libMflacCrypto.so`：`Java_com_ikunshare_sound_utils_MflacCrypto_nativeInit`(0xa50)、`nativeRelease`(0xea8)、`nativeDecryptChunk`(0xeec)
- Dart 通道名：`com.cenmusic.app/mflac_crypto`；类：`MflacDecryptingAudioSource` / `MflacNativeDecryptor` / `MflacCryptoException`

即：它能在本地解密 QQ 音乐的 `.mflac` / `.mgg` 加密音频再播放。**这不是 HTTP 接口，是本地解密能力**，放在第 7 节单列。

## 2. 取证方法（可复现）

1. 解包 APK，只取 `lib/arm64-v8a/libapp.so`、`libcenbridge.so`、`libMflacCrypto.so` 与 `classes.dex`。
2. 对 Dart 快照做 ASCII 串扫描：抽全部 `http(s)` 字面量、域名、以 `/api` `/openapi` `/newh5app` `/mobi` 开头的路径，以及 `Kw*` / `Song*` / `Lyric*` 类名与方法名。
3. 对每个端点做 ±600～900 字节邻域串打印，还原它与哪些参数名、模型类（`KwAlbumDetail.fromJson`、`KwComment.fromJson`、`KwCatalogItem.fromPlaylist` 等）相邻。
4. 对能直连的端点做**只读 GET 探活**（不带任何写操作），确认 2026-11-11 当天是否仍可用、返回什么结构。
5. 与本机 `JZMusicHelperAndroid/app/src/main/java/com/jz/musichelper/network/` 下 15 个 `.kt` 的端点逐条比对。

标记约定：**实测** = 本次真的调通并看到结构；**待验** = 端点在包里存在，但需要 cookie/加密参数，本次未打通。

## 4. 封面 API（笒音侧）

酷我不提供「传 id 就出图」的固定拼法，封面路径由接口字段给出，App 只做 host/尺寸归一化（`kwNormalizePic`、`kwPickArtistPic` 两个函数名在快照里）。三种形态：

| 形态 | 实测可用的 URL 形态 | 路径来源 | 我方 |
| --- | --- | --- | --- |
| 曲图（横版/竖版共用） | `https://img1.kuwo.cn/wmvpic/{size}/{hash}/{n}/{rid}.jpg`，例：`https://img1.kuwo.cn/wmvpic/324/s4s36/41/926857763.jpg` → 200 image/jpeg | `r.s` 记录的 `MVPIC` 字段（如 `324/s4s36/41/926857763.jpg`） | **没有** |
| 专辑图 | `http(s)://img2.kuwo.cn/star/albumcover/{size}/{hash}/{n}/{rid}.jpg`，例：`http://img2.kuwo.cn/star/albumcover/300/s4s60/3/1960699163.jpg` → 200 image/jpeg | 推荐流 `img` 字段 | **没有** |
| 歌手头像 | `https://img1.kuwo.cn/star/starheads/…`（裸 id 取不到，必须带接口给的 hash 路径） | 歌手接口的 `ARTISTPIC` / `headPic` | **没有** |
| 歌单封面 | `http://img1.kwcdn.kuwo.cn/star/userpl2015/...`（`kwcdn` 域名） | `getRcmPlayList` 的 `img` | **没有** |
| 尺寸归一化 | 包内常量出现 `/240/`；接口默认给 `300` | — | — |

我们现在的封面只有两种来源：QQ 专辑图 `https://y.gtimg.cn/music/photo_new/T002R300x300M000{albumMid}.jpg`，以及各平台搜索返回的 `picUrl`。
酷我搜索我们没取 `MVPIC`（`Song(... picUrl = null)`），酷狗 `imgessl` 已判死走 QQ 兜底。**因此酷我封面在我们这边是 0 覆盖。**

## 7. 反向对照：我们有、它没有的

它是**单源**（酷我在线 + 本地文件），所以这几块它没有：

- 网易云搜索 `music.163.com/api/search/get` 与网易云取流（我们经 gdstudio / oiapi）；
- QQ 官方聚合取流 `u.y.qq.com/cgi-bin/musicu.fcg` 与 `cyapi.top` QQ 兜底；
- 酷狗听歌识曲指纹 `gateway.kugou.com/fingerprint.service/v1/music_trackid_mulit`（8 秒 16k 单声道 PCM）；
- 酷狗 KRC 逐字歌词（`lyrics.kugou.com/v1/search` + `/download`）与 QQ QRC 逐字（`musicu.fcg`）；
- 跨平台换源重试与变体过滤（我们搜索层做了去重 + 原曲判定）。

也就是说：**它强在酷我这一条链的完整度（取流/封面/歌词/歌单/评论全通），我们强在多源与识曲、逐字歌词。**

## 8. 边界与未解项（不装懂）

1. `mobi.kuwo.cn/mobi.s` 的 `q`（`f=kuwo&q=`）**加密构造未解出**。包内没有 `corp=kuwo`、`ylzsxkwm` 这类明文密钥，只有 `convert_url_with_sign` 与 `kwplayer_ar_12.0.6.4` 两个线索；要拿到 q 需要动态抓一次真实请求，或对 Dart 快照做反编译（本机无 Dart SDK / blutter / MSVC，本次未做）。
2. `mobiweb.s` 的用途未确认（推测为 web 侧聚合/歌词变体），同样卡在 q。
3. `albumInfo` / `playListInfo` / `playlist/detail` / `getTagPlayList` / `com.s` 这 5 个是**端点存在但本次没打通**：需要 web 侧 cookie（`csrf`/`kw_token`）或正确的 tag/pid 参数，报错分别是 `The request is illegal!`、404、604。没有把它们标成「可用」。
4. 网易云在该包里只承担皮肤商店，**没有**歌曲搜索/取流/歌词调用；如果它还有隐藏调用，静态串里没有痕迹。
5. 本次只做只读 GET 探活，没有登录、没有写操作、没有下载音频。

## 10. 接入建议（哪些该融进我们，哪些不该）

结论：**只融三条，按成本从低到高**。前两条不新增任何「取流」，只是把已有响应里的字段用起来。

### 第 1 优先：酷我封面（零成本，当天可落，收益最大）

- 做法：`KuwoSearchAdapter` 解析 `MVPIC`，拼 `https://img1.kuwo.cn/wmvpic/{MVPIC}` 直接当 `picUrl`。
- 实测：`周杰伦/陈奕迅/五月天` 各 20 条搜索结果中，`MVPIC` 非空 19/15/13 条，合计 **47/60 = 78%**；随机抽 4 条拼出的 URL 全部 `200 image/jpeg`（5.7–9.4 KB，324px）。
- 收益：我们目前 `Song(MusicPlatform.KUWO, …, null)`，酷我封面 **0 覆盖**、全靠 QQ 同名同歌手兜底（同名不同专辑会换错图）。改造后约 4/5 直接有真图，剩余 1/5 才走兜底。

### 第 2 优先：酷我歌词（零成本，当天可落）

- 做法：`LyricsService` 加 `KUWO` 分支，`getlyric?musicId=<MUSICRID 数字>&httpsStatus=1`，取 `lrclist` 转 `LrcLine(time, text)`；`lrclist` 为空时用 `getUnsynchronisedLyric` 兜底。
- 实测：按搜索结果取 40 首（周杰伦/陈奕迅/五月天/林俊杰 各 10）逐条查询，**40/40 命中**，行数 29–92 行；`time` 是秒（两位小数），需转毫秒。
- 注意两点：① 它是**行级**时间，不能做逐字染色，只在酷狗 KRC / QQ QRC 都拿不到时用它；② 参数必须是纯数字 rid（传 `MUSIC_1433923026` 会返回 `参数错误`），传错 id 会返回 `data:{}` 而不是报错，要判空。

### 第 3 优先：酷我官方取流（值得做，但要先抓一次包）

- 做法：`mobi.kuwo.cn/mobi.s?f=kuwo&q=…`，`q` 内是 `type=convert_url_with_sign` 的签名请求，客户端标识 `kwplayer_ar_12.0.6.4`；`MINFO` 已给各档位（flac/320/192/128…），可按档取。
- 现状：`q` 的加密构造没解出来，裸调 404；本机无设备、无 Dart SDK，**必须先用一次真实请求抓包**（跑一次笒音、或对 `libapp.so` 做 Dart 反编译），才能落地。
- 收益：酷我不再依赖第三方「妖狐」，签名直链稳定、档位可控；建议做成「mobi 优先，失败退妖狐」，不要直接替换。
- 风险：签名参数随客户端版本变化，属于最易失效的一条。

### 明确不建议融进来的

| 接口 | 为什么不 |
| --- | --- |
| `discover/v0` 推荐流、`getRcmPlayList` 歌单、`getTagPlayList`、`playListInfo`、`albumInfo`、`comment.kuwo.cn/com.s` | 这些是**功能扩展**（推荐页/歌单页/评论页），不解决「封面/音乐/歌词残缺」；且专辑/歌单/评论需要 cookie 或加密 q（实测 `request is illegal` / 404 / 604），稳定性最差 |
| `searchKey` 联想词 | 只是搜索框下拉，体感收益远低于封面歌词，可等 UI 迭代时再加 |
| MV（`KwMvInfo` / `MP4*`） | 需要播放器与横屏形态，属于新模块，不是修残缺 |
| `mflac` / `mgg` 解密 | 只对「本地 QQ 加密文件」有意义，跟在线取流无关；且涉及版权保护机制，不建议引入 |
| 网易云 `skin/list`、`q1.qlogo.cn` | 皮肤商店与 QQ 头像，跟本次目标无关 |

补充一条不属于笒音的：网易云封面我们也可以自己补——`music.163.com/api/song/detail?ids=` 返回 `album.picUrl` 是完整直链，能一次解决网易云封面同样 0 覆盖的问题，成本与第 1 条相当。

### 落地顺序建议

1. 封面（酷我 `MVPIC`）→ 2. 歌词（酷我 `getlyric`）→ 3. 取流（先抓包验证 `q`，再做 mobi 优先 + 妖狐兜底）。

前两步各是一处小改，不引入新的失败面；第三步在没抓到 `q` 之前不要动手，否则只能写死一个会过期的签名。
