## v2.1.91 ｜ 识曲改成酷狗＋网易双通道互为兜底

**这次的改动**：一条听歌识曲里跑两条通道，谁认得出就用谁。

- 先录到 6 秒就问一次酷狗，**认出就立刻出结果**（常见情况仍是 6~7 秒，和以前一样快）
- 6 秒没对上，继续录满 12 秒，用完整片段**同时**打酷狗与网易：酷狗优先，**酷狗找不到的由网易找**
- 网易这条同时也在跑酷狗第二遍（片段更长更稳），所以**网易找不到的由酷狗找**
- 时长档位同步收成 12／15／20 秒（12 秒是网易指纹的最低窗口），旧设置里的 5 秒、10 秒自动按 12 秒处理

**网易这一路为什么免费**：不接 ACRCloud / AudD 这类付费服务，也不需要 key。指纹在手机本地由网易自家 afp 引擎算出来（随包带约 400KB 引擎资源，WebView 承载），再拿它去召回网易曲库的中文元数据。

**实测数据（桌面同一份引擎资产）**

| 项目 | 结果 |
|---|---|
| 指纹生成 | 61~76ms，长度 3008~4268 字符 |
| 网易接口 | HTTP 200 / code=200 / noMatchReason=0 |
| 原唱可达 | 《晴天》返回「晴天 / 周杰伦 / 专辑《叶惠美》/ 269 秒」 |
| 候选噪声 | 同一条音频也会回翻唱（「晴天 / 王先森」「晴天(深情版)」），已按「非现场非改编 → 专辑不等于歌名 → 标题最短」排序后再取第一 |

**交付验证（apk-verify 口径，21 项全 PASS）**：版本三方一致 2.1.91 / vc149、包名、minSdk 26 / target 34、签名证书 SHA-256 与既定一致、zip 无损坏条目、体积 29,859,137 B、三份引擎资源已打入且与源码逐字节一致（recognizer.html / afp_wasm_b64.js / sandbox.bundle.js）、dex 文案断言、清单含 INTERNET 与 RECORD_AUDIO、设置页正文无 ASCII 双引号。

**这次额外做的一层验证**：本机没有真机也没有模拟器，所以用桌面 Chromium（Blink，和 Android WebView 同引擎）加载**打进包里那一份** recognizer.html 实测：页面 ready、`__encode` 回调成功、指纹 4120 字符、网易命中 3 条——证明 JS 桥这条路径本身是通的。

**已知缺口**：没有设备，WebView 在真机上的首次编译耗时、内存占用、以及 512KB base64 跨 JS 桥的实际表现未做真机验证。若某台机器上 WebView 起不来，代码会**静默跳过网易、继续只走酷狗**，不会把识曲卡死或报错。
