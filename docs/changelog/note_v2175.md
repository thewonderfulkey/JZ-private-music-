# v2.1.75 桌面歌词「开了不显示」修复

版本：v2.1.75 / versionCode 133　包名 com.jz.musichelper
产物：JZ音乐助手-v2.1.75.apk　29,634,383 B　MD5 `BE0B8D4124AC05E3CBA79514063925D1`

## 一、你录屏里发生的事

- t12.0–t12.5 三点菜单显示「桌面歌词 · 已开」（当时是开着的）
- t14.0 点一下 → toast「桌面歌词已关闭」
- t16.0 再点 → toast「桌面歌词已开启，回到桌面（或切到别的应用）播放时即可看到」
  —— 这里没有出现「需要权限」的提示，说明**悬浮窗权限当时是给到的**
- t18.5 回到桌面，到 t25.5 一直在桌面图标页/天气组件页之间切换，**全程没有歌词栏**
- 同时歌曲在播（进度 0:00→0:20 在走，按钮是「Ⅱ」）

所以不是权限问题，也不是没在播歌，而是**窗口根本没挂上去**。

## 二、根因：三个环节互相等，谁都迈不出第一步

v2.1.74 里挂窗的判断是这样写的：

```
挂窗 = 开关开着 && 有悬浮窗权限 && App 不在前台 && 当前歌曲 != null
```

而"当前歌曲"（内部叫 songKey）只有 `syncFromSources()` 会写，`syncFromSources()` 只在 200ms 的 ticker 里跑，ticker 又只有在 **窗口已经挂上之后**（`attach()`）或"检测到切歌"（`onSongChanged()`，本身由 ticker 触发）时才会启动。

结果就是：

- 窗口要等"当前歌曲"才挂 → 没有窗口就没人跑 ticker → 没人写"当前歌曲" → 窗口永远不挂。

三条腿的凳子互相当腿，桌面歌词因此一次都没出现过。这类死锁编译能过、静态检查能过、预览图也照样好看，只有真机操作才暴露——上次交付时没有设备，这是漏掉的那一环。

顺带两处同源问题一起修了：

1. 首次挂窗时 `playing` 还是初始的 false，会先闪一下"暂停"变灰标记。
2. 没有在播歌时，挂窗后立刻被拆掉并停掉 ticker，之后从通知栏/自动连播起歌就再也发现不了。

## 三、这次改了什么（4 处，都在桌面歌词这条链上）

1. `data/DesktopLyrics.kt` · `syncWindow()`：闸门去掉「当前歌曲 != null」，改为 **开关开着 + 有权限 + App 不在前台** 就挂窗；歌名由 `attach()` 立刻补拉一次。
2. `data/DesktopLyrics.kt` · `attach()`：挂窗成功后重排为先对齐真实播放状态 → 起 ticker → 立刻 `syncFromSources()` → 再画首帧（"歌词加载中…"/上一首残留内容）。这样窗口一出现就有内容，不用等下一拍。
3. `data/DesktopLyrics.kt` · 无歌曲分支：不再 `detach + stopTicker`，改为窗口留着显示「暂无歌词」并继续循环，从通知栏/自动连播起歌也能马上接到词。
4. `data/DesktopLyrics.kt` · 挂窗失败时（权限为真但系统二次拦截，比如 ROM 自己的"悬浮窗"总开关没开）写入 `lastError`，`ui/SettingsScreen.kt` 在桌面歌词状态下方用深赭色直接显示这句话，不再静默失败。
   另：`ui/DesktopLyricsView.kt` 的霞鹜文楷改为进程内缓存一次（19MB 字体每次挂窗重解会卡）。

界面、交互、视觉口径全部不动：仍是两行（当前行 15sp 墨色 / 下一行 13sp 灰）、300ms 换行、暂停保留最后一帧变灰并带「‖」、底部居中偏上 120dp、拖动吸边、转屏按比例复位。

## 五、30 秒自查步骤（装好后）

1. 播放任意一首有词的歌；
2. 设置页或播放页三点菜单打开「桌面歌词」（第一次会跳到授权页，允许「显示在其他应用上层」）；
3. 按 Home 回桌面 → 屏幕底部应出现一条两行歌词栏，逐行跟着走；
4. 下拉通知栏暂停 → 当前行变灰并在右侧出现「‖」，位置不动；
5. 按住歌词栏拖动 → 松手自动留边；转屏后仍在同一相对位置。

如果第 3 步还是没有：现在设置页「桌面歌词」下方会直接写出系统给的原因（例如"系统拦截了悬浮窗…"），把那句话截图发来即可，不用再靠猜。
