**JZ音乐助手 v2.1.69（测试版，GitHub 未发布）**

继续查了你说的"息屏就卡住、一直不切下一首"。结论：**网络模块有问题，但它不是第一层**——真正先出问题的是"播完这个事件根本没送到 App"。

**读代码后的两个确定缺陷**
1. v2.1.68 里那个出网探测是**阻塞调用**，却被自动连播的协程（主线程）直接调用：网络不通时一次最多卡主线程 6 秒，等网络时每 4 秒来一次。主线程几乎被打死，播放回调、取流编排全都排不上队——这本身就会表现成"卡住不动"。
2. 判定"这首唱完了"**只依赖 MediaPlayer 的完成回调**。息屏进 Doze 后系统会忽略 wakelock、冻结后台，音频在音频硬件里已经放完，但回调要 CPU 醒着才投递——回调不来，代码就永远以为"还在播"，于是既不切歌也不报错，正是你看到的"一直卡在上一首"。

**这版改了什么**
- 出网探测改到 IO 线程（`Dispatchers.IO`），主线程不再被卡。
- 息屏时取流失败**一律**按"等网络"处理：不判无源、不消耗跳过额度、不自动跳歌；屏幕亮着且网络恢复才续播，退避 4s→10s→30s，最长等 45 分钟。
- 新增**曲终闹铃**：每首歌开播时按剩余时长排一个到点唤醒的闹铃（Doze 下闹铃仍会投递）。到点核对进度确实到底，就直接推进下一首，不再等那个可能永远不来的回调。
- 新增**播完看门狗**（3 秒一次）：播放中 + 进度到底 + 连续两个周期没动 → 按播完处理，切下一首。
- 亮屏兜底也补了这种情况：亮屏发现"播放中但进度停在末尾"，直接按播完推进。
- 设置页「播放日志」顶部新增状态行：屏幕亮/灭、Doze 是/否、电池白名单 已允许/未允许，配合日志可以直接看出卡在哪一层。

**需要你做一件事**：设置 → 息屏连播 → 点「去允许」，把 App 加进系统电池白名单。不加的话，Doze 仍会掐网络，只能靠闹铃"到点推进 + 亮屏补播"，起播时间点会延后。
