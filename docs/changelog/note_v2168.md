**JZ音乐助手 v2.1.68（测试版，GitHub 未发布）**

针对你反馈的：《苦瓜》播完切《蒲公英的约定》长时间无声 → 打开 App 取流成功刚出声又被自动切下一首。你说的方向对了一半：确实是"超时自动切换"那块在补刀，但它背后还有一个更前置的原因——息屏后取流本身失败了。

**两个原因**
1. 息屏久了系统会限制后台联网（Doze）。这时取流失败，代码把它当成"这首歌没有播放源"，于是计入跳过额度、600ms 后自动切下一首；连续 3 首失败就在你没看的时候把队列静默跳过去了——你听到的"长时间无声"其实就是它在空转。
2. 这个"自动跳下一首"的任务排上之后没有作废机制。你重新打开 App、网络恢复、取流成功、刚开始出声，上一轮排着的跳歌任务（或上一首歌迟到的播放回调）又执行了一次 → 刚出声就被切走。

**这版改了什么**
- 取流彻底失败后先做一次出网探测：判定是"网络被系统限流"就不跳歌、不消耗跳过额度，原地每 4 秒探一次，最多等 15 分钟，网络一回来就续播同一首。
- "自动跳歌"任务统一收进一个句柄，新歌起播时立刻作废；执行前再确认一次"当前确实没有歌在播"，否则不跳。
- 播放器的播完/出错回调加"代次"校验，上一首歌迟到的回调不会再动到刚响起的新歌。
- 亮屏/解锁时兜底重试：息屏时没取到的歌，回到界面立刻重新取流并续播。
- 设置页新增「息屏连播」：可以把 App 加进系统电池白名单（**请务必点一次"去允许"**，否则锁屏久了后台网络还是会被掐）。
- 设置页「播放日志」会显示最近 14 条播放事件（起播/播完/取流失败/跳歌），复现后截图给我，就能精确看到卡在哪一步。

**静态验证**：assembleRelease 成功；vc126 / 2.1.68；包名 com.jz.musichelper；签名证书 SHA-256 与历史一致（916ad232…07ac）；zip 183 条目无损坏；权限含 WAKE_LOCK 与 REQUEST_IGNORE_BATTERY_OPTIMIZATIONS。
**缺口**：本机没有可用真机（adb 无设备），以上均为静态验证，实际息屏连播需要你在真机上复现确认。

**测试建议**：设置 → 息屏连播 → 去允许；然后按同一条链路点《最近播放》，锁屏等《我不配》播完 → 看是否自动到《苦瓜》，再等《苦瓜》播完 → 看是否到《蒲公英的约定》。如果仍有异常，把设置页「播放日志」截图发我。
