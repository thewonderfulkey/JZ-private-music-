#### 二、猜你喜欢解析：与搜索彻底统一为同一套逻辑

你判断得对——**原来确实不是同一套**：
- 猜你喜欢的歌来自搜索池，但被挑中的是**单平台条目**（多为网易云）。旧逻辑只试「该平台自己的后端」，两个网易云后端一挂就直接判无源，进入 10 轮重试（累计十几秒），最后跳过。
- 而搜索同一首歌时，结果里通常带 QQ 条目，走 QQ 直连 0.3s 出链，所以"搜索秒解析"。

v2.1.29 改成三级解析，任何入口（猜你喜欢 / 搜索 / 热门 / 收藏 / 历史 / 自动连播）行为完全一致：

1. **第 1 级**：本平台后端 与 妖狐酷我（按歌名+歌手搜索同曲）**并发首发**，谁先解析成功用谁。不再串行等两个后端各自超时（旧逻辑最坏 24s，改后典型 1~2s）。
2. **第 2 级**：仍失败时启动**同曲跨平台补源**——调用与搜索**完全相同**的 `SearchService.searchAll`，把 QQ / 网易云 / 酷我 里**同歌手同歌曲**的候选全部取出（最多 8 条），逐条用候选自己平台的后端取流，任意一条成功即播放。
3. **只有第 1、2 级所有同歌手同歌曲条目全部解析失败**，才计入"无源"并走自动跳过（跳过上限 3 首、间隔 0.6s）。

顺带修掉两类"明明能解析却被误杀"的判断 bug：
- **多歌手串**：`谭晶/陈奕迅`、`陈奕迅、谭晶`、`陈奕迅 谭晶` 这类写法原来整串比对，必然对不上。现按单人拆分后取交集，只要有共同歌手即认。
- **版本后缀**：`富士山下（Live）` 与 `富士山下` 原来判为不同曲。现先剥离括号版本说明与标点，再按"相等或互相包含（长度差 ≤6 字）"认定，同时用时长差 >12s 拦掉真正的不同版本。

重试参数同步收敛：`RESOLVE_RETRY_MAX` 10 → 3，延迟 2000/2500/3000ms。三级已覆盖跨平台，不需要再盲等十轮。

建议你重点验证：录屏里那几首猜你喜欢的歌（《龙文》《青蛙王子》等）点击后是否直接出声、不再长时间卡在同一首。
