## JZ音乐助手 v2.1.30 — 悬浮栏切歌修复 + 猜你喜欢/编辑精选取录音棚原唱

针对 11:38 那条录屏（38s）提的两条意见，本轮逐条整改。

### 一、悬浮栏左右切歌点不动

**现象确认**：38s 录屏 34~38s 逐 0.25s 抽帧，悬浮条全程停在《龙文》，连点无任何变化，也看不到按压反馈。

**根因**（两处叠加，都指向"点了等于没点"）：

1. **命中断层**：v2.1.29 按反馈去掉钮框后，四个钮只剩 40dp 透明热区，而 `inkClickable` 的 `graphicsLayer` 还带 0.93 缩放，实际可命中的范围进一步缩小；画卷 `drawBehind` 整幅铺底后，手指落在钮边缘或钮与钮之间的缝里就完全命不中，按压动画也不触发——这正是录屏里"点了没反应"的样子。
2. **队列为空/单曲时静默返回**：`nextSong` 第一行 `playlist.isEmpty()` 直接 return；队列只有 1 首时 `(idx+1)%1` 原地不动。从编辑精选进入时若此前没有队列，左右切歌就必然无反应。

**修法**：

- 悬浮栏最上层新增一条**手势通道**（与画卷等宽），按归一化 x 分区命中：`<0.50` 打开播放页 / `0.50~0.616` 收藏 / `0.616~0.728` 上一曲 / `0.728~0.840` 暂停·播放 / `≥0.840` 下一曲。点中即执行，不再依赖子元素命中测试，也不再受缩放影响。
- 纵向只认按钮所在带区（高度 18%~82%），画卷上下的山水留白不接管点击，避免在画面上随便一点就被切歌。
- **按压反馈保留**：按下时不消费事件，下层 `inkClickable` 照常进入按压态（缩放+压暗）；抬起时由手势层消费并分发，避免同一次点击执行两次。手势层万一失效，下层原点击仍可兜底。
- 队列兜底：`openSong` 队列为空时兜底成单曲队列；`nextSong`/`prevSong` 在 0 首/1 首时用「当前歌 + 收藏 + 最近播放」补齐，单曲时改为重新取流，不再静默 return。
- 随机模式下"上一曲"也走随机，与下一曲行为一致。
- 切歌取流期间副标题显示「正在取流…」，把"已生效但还在解析"与"点了没反应"区分开。

### 二、猜你喜欢 / 编辑精选 尽可能取录音棚原唱

**举证核查**：QQ、网易各拉 20 条《龙文》候选，"龙文"这个名字下同时存在近 40 个条目——现场版 6 条、春晚/跨年/盛典版、合唱版、童声版、古筝版、版本1/版本5、多方翻唱。

- 录音室原唱：谭晶《看见》，313s（QQ `001RBlzR3ZEQhK` / 网易 `26217044`），另有网易 `1335942982`《时代·记忆》311s。
- App 此前播的：QQ `004EnVa83aE4qu`「龙文 / 谭晶;陈奕迅 / 无专辑 / 243s」，封面是现场演出照——与"开头有掌声、节目消音"的描述完全对得上。

**修法**：新增 `StudioPick`（录音室原唱优选），四个维度打分后择优：

1. **裸名**——剥掉括号版本说明与「- Live」「伴奏」等修饰后缀后仍等于原名，才算原版名；
2. **专辑**——现场/演唱会/春晚/晚会/盛典/综艺/新声代/天赐/蒙面等命中即重罚，有正式专辑加分；
3. **时长**——与同曲共识时长（多平台多数条目，±10s 分桶取众数）差 ≤12s 加分，>30s 视为剪辑/片段重罚；
4. **单歌手优先**——合唱版、群星版降权。

接入点：

- 猜你喜欢候选池按核心歌名**归并择优**（同一首歌只保留最像录音室原唱的一条，此前节目版与原唱同池竞争，滚动一次就可能抽到带掌声的）；
- 编辑精选点歌、后台补齐歌单、跨平台补源候选排序，全部改为择优；
- 搜索条数 10 → 30（原版常被 Live/翻唱挤出前 10，取不到就只能回落节目版）；
- 猜你喜欢缓存版本 2 → 3，安装后旧缓存自动作废重算，不会继续显示旧的节目版。

**验证**：把同一套打分逻辑在 python 里独立复刻，喂入实测的 40 条《龙文》候选——QQ、网易、合并池三组都选出 313s 谭晶《看见》；节目版 243s 得分 18，原唱 165；全部 Live/春晚条目 -91 ~ -224。
