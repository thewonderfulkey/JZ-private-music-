#### JZ的音乐助手 v2.1.81：修「已授权却报未授权/识别失败」+ 首页识曲栏重做

##### 一、先说结论：不是权限问题，是我们自己把「取消」当成了「失败」

你截图里那行英文 `The coroutine scope left the composition` 就是证据。

- 上一版把「录音 + 上传识别」这段耗时任务放在了识曲浮层内部执行。浮层一旦被移除（点「重试」、授权弹窗返回、关掉浮层都会移除），Compose 会取消这段任务并抛出一个**取消异常**；
- 我们的代码把「取消异常」和「真失败」一起兜成了失败，于是界面把英文异常原文直接显示出来——所以看起来像"识别失败"，其实是被我们自己打断的；
- 连带着「重试」也永远失败：点重试 = 先移除旧浮层 → 旧任务被取消 → 那条取消异常又被当成失败。

权限这边反而是好的：你那张系统「麦克风权限」页截图里，版本 2.1.80、选中「仅使用期间允许」，说明权限确实授予了。

##### 二、这版怎么修的

1. **识曲全程搬到应用级作用域**：录制与识别不再依附浮层，浮层只负责显示状态。重试、授权返回、关浮层都不会再把任务掐断；真取消和真失败分开处理。
2. **两种真机坑一并堵上**（它们也会造成"未授权"的错觉）：
   - 麦克风刚被释放、或正被录屏/通话占着时，第一次建不起来 → 现在失败会隔 350ms 再试一次；
   - 少数机型 8k 采样率不被接受 → 自动退回 16k 采集，再按 2:1 抽点降到 8k 送识别（接口只认 8k，这一步是本机实测踩出来的）。
3. **界面不再出现英文异常**：所有失败都翻成一句人话——「麦克风被占用或系统没放开（关掉录屏/语音通话再试）」「网络不通」「这次没录到声音」「曲库里没对上」等。
4. **识别成功/失败的行为**：认出歌名歌手后直接进结果卡（「去播放」一键进播放页）；没认出来提示换个安静点的地方再试。

##### 五、装包与验收建议

覆盖安装即可（同签名，数据保留）。建议按这个顺序试：

1. 首页点那枚圆形麦克风 → 首次若弹权限，允许后应直接进入 listening（"还能听 N 秒"）；
2. 录制中途点「取消」，再点一次麦克风重开 → 不应再出现英文异常；
3. 识别失败时点「重试」→ 现在应正常重录，而不是立刻又失败；
4. 放一首歌外放，靠近手机识别 → 应出歌名歌手，点「去播放」进播放页。

如果第 4 条仍然认不出来（不是崩、不是取消，而是走完 10 秒后提示「曲库里没对上」），那是曲库/音频口径问题，不是这次修的这条链路；告诉我，我再上备用方案。
