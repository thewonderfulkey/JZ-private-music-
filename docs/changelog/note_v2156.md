## JZ 音乐助手 v2.1.56：开屏收尾改成「音符缩小 + 音符放大」两段

亚楠说的那条已改：以前是「画面整片变黑 → 黑了之后音符放大」，现在变成一条连贯的手势 —— **山水收进一枚墨音符（音符缩小），再由这枚音符放大把音乐界面让出来**，两段都能看清。

### 这一段具体怎么动
1. **第一段 · 墨从四周合拢（约 0.33 秒）**
   墨先把画面压到「一大枚音符」，然后这枚音符里的山水越缩越小，一路收到正中一枚小音符。
   - 前 0.07 秒快速到位（不再有「慢慢变黑」的拖沓感）；
   - 剩下 0.26 秒按等比例缩，每一帧缩同样的比例，所以中段、后段都看得清它是音符在缩；
   - 最后 0.07 秒音符里的小块山水转成纸色，收尾是「黑底上一枚纸音符」，不是凭空蹦一个洞。
2. **第二段 · 音符放大（约 0.36 秒）**
   首页真画出第一帧后，这枚纸音符放大，音乐界面从音符的形状里被让出来。
   - 前 0.15 秒音符慢慢长大（不再是「一帧跳满」）；
   - 后 0.21 秒按面积匀速铺开，最后不会猛地一抖；
   - 中间等首页就绪最多只压 0.38 秒（黑底上一枚纸音符，看着是有意为之）。
3. **「跳 过」**走同一条路，只是快一倍（0.14 秒收 + 0.16 秒放），不会再闪一下黑。

合计「墨合拢 → 界面出来」约 0.69 秒（比上一版 0.62 秒略长一点，但这 0.69 秒里有两段看得清的音符缩/放，不是原来那种「黑一下再跳出来」）。

### 技术口径（没换套路，还是老约束）
- 仍然是「一条音符形状的裁剪路径」：合拢段用墨色环压住开口以外，放大段用 `ClipOp.Difference` 把开口从开屏层减掉，露出下层首页。
- 不碰 Compose 的混合模式（本机 `DstIn` 那套已知不可靠），不碰路径布尔运算。
- 裁剪的两段都用同一份 `noteHolePath`（符头 + 符干 + 符尾），保证「缩完的那枚音符」和「放大的那枚音符」是同一枚，不会错位。
