## 1. 识曲页「最近识过」贴底，与播放悬浮栏严丝合缝

**原因**：列表用的是 `Column + verticalScroll` 顶对齐。条目少时，内容只占上方一小块，
下面是一整片空白，看起来像"列表断了"。而且末尾还留着 v2.1.85 为防遮挡加的 84dp 让位。

**改法**：换成 `LazyColumn(verticalArrangement = Arrangement.Bottom)`，条目少时整列贴底；
末尾让位从 84dp 调到 **64dp**。同时删掉页面底部那行被悬浮栏挡住的说明文字——
它占了约 24dp，会让"贴底"算不准。

> 踩坑记录：第一版只写了 `Modifier.fillMaxWidth()`，`LazyColumn` 高度=内容高，
> `Arrangement.Bottom` 没有多余空间可分配，列表照样顶对齐。必须加 `weight(1f)`。

**实测**（模拟器 1080×2340，density 440）：调整前最后一条底部 1774px、悬浮栏上沿约 1838px，
差 64px；改 64dp 后最后一条落在 1838px，视觉上正好压在栏上沿。

## 2. 去掉「N 平台并发」

四平台恢复后这行会折成两行（截图里就是"4 平台并 / 发"）。左侧每个平台自己的条数
（QQ 50 / 网易 50 / 酷我 41 / 酷狗 30）已经说明一切，删掉这行，只留一个 `Spacer(weight)` 撑住布局。

## 3. 酷我的歌不再显示 `--:--`

**原因**：酷我 `r.s` 的 `DURATION` 是**秒数**（实测 262、334），而 `parseDuration` 只认 `mm:ss`，
纯数字落进 else 分支返回 0 → 时长显示 `--:--`。

**改法**：先尝试 `toIntOrNull()`，落在 1..36000 就当秒数；否则再按 `mm:ss` / `h:mm:ss` 解析。

**实测**：搜索结果里酷我的条目现在显示 04:52 / 04:17。

## 4. 结果行右列对齐（时长 / 红心 / 平台标签）

**原因**：时长文本与平台标签都是"按内容定宽"（`04:23` vs `--:--`、`QQ` vs `网易`），
每行宽度不同 → 红心和标签的横坐标逐行漂移。

**改法**：两者都定宽：
- 时长 `Modifier.width(42.dp)` + `TextAlign.End`
- 平台标签 `.width(44.dp)` + `TextAlign.Center`

**实测**：搜索结果每一行的时长右边缘、红心、标签都在同一条竖线上。
