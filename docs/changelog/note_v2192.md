## 一、这版改的是判定口径，不是加通道

v2.1.91 是「酷狗先问、命中就返回，网易只兜底」。问题出在这句话上：**指纹接口只回它曲库里最像的那一条，那条可能是别人的翻唱**。酷狗一旦给出翻唱，网易手里的原唱连参与比较的机会都没有。

用户给的例子正是这样：张杰《我们都一样》，酷狗总是给别人的版本，网易有张杰的原唱，但旧逻辑下永远走不到网易。

这版把「谁先返回」换成「谁的证据更硬」：**两条通道都跑完 → 按同一首歌归并 → 统一打分 → 取最高分。**

## 二、打分模型（全部可解释，没有拍脑袋的渠道偏好）

单条候选分（`RecognizeScore.memberScore`）：

| 证据 | 分值 | 理由 |
|---|---|---|
| 酷狗 `is_original = 1`（原唱） | **+45** | 最硬的单点证据。实抓《晴天》验证：周杰伦=1、凌霄(庄云霄)=2、小柒=0 |
| `is_original = 2`（翻唱/他人版本） | **−30** | 同上 |
| 歌名是裸名（`StudioPick.isCleanTitle`） | +12 | 原版多为裸名 |
| 歌名带 `(Live)`／`伴奏`／`【AI翻唱】` 等 | −35 | 版本说明是噪音 |
| 专辑是正式独立专辑 | +15 | 原唱必有正式专辑 |
| 专辑名 == 歌名（同名合集/自建合集） | −20 | 网易翻唱的典型特征 |
| 专辑是现场/综艺/节目 | −28 | 节目 Live 不是原唱 |
| 完全没有专辑信息 | −8 | |
| 时长可解析（30s~30min） | +4 | 作为互证原料 |
| 通道内位次（第 1 条起） | +7 / +5 / +3 / +1 / 0 | 指纹接口按相似度排序，位次本身有信息量 |
| 来自网易 | +2 | 多给专辑/时长/songId，元数据更完整（仅作微调） |

身份级加成（同一「核心歌名 + 第一位歌手」的候选合并算）：

| 证据 | 分值 | 理由 |
|---|---|---|
| 两条通道都命中同一身份 | **+50** | 互证比任何单点特征都可信 |
| 同歌手 ≥2 张不同正式专辑、这些条目时长互差 ≤3s | **+22** | v2.1.90 的 D 口径：「同一版录音被反复收录」才算原唱 |

## 三、用真实数据验证（不是只跑编译）

**夹具 A：真实响应。** 2026-11-12 我重新打了酷狗指纹接口（音频取自现存的《晴天》10 秒样本），拿到 5 条真实候选；网易 3 条取自工作目录里留存的真实响应（`ncm_case1`）：

```
酷狗 5 条：周杰伦/叶惠美/269s/orig=1、凌霄(庄云霄)/继续寻找周杰伦/269s/orig=2、
          HanMoon/无专辑/orig=0、小柒/抖音热歌飙升榜/orig=0、77z/162s/orig=2
网易 3 条：丹尼尔在的晴天、晴天/王先森/鸭力大呀/314s、晴天/雷米克斯/晴天/125s
结果：周杰伦 83 分 > 王先森 38 > 小柒 28 > HanMoon 7 > 凌霄 6 → 采用酷狗 ✓
```

**夹具 B：用户的场景**（酷狗只给翻唱、网易给原唱）：

```
酷狗：我们都一样/神仙哥哥/专辑《我们都一样》/orig=2      → −27
网易：我们都一样/张杰/《明天过后》302s
      我们都一样/张杰/《One Chance 新歌+精选》303s        → 40 + 22（双专辑+时长互证）= 62
结果：张杰 62 分 > 神仙哥哥 −27 → **采用网易** ✓
```

**其他场景**：只有酷狗 → 周杰伦 83；只有网易 → 王先森 38（没有更好选择）；两边都给周杰伦 → 133（互证加成）；识曲命中综艺版（张杰、胡迪、范如臣/《异口同声 第十二期》）→ 归并到「张杰」身份，90 分落到原唱。

> 说明：这些分数是用与 Kotlin 同构的 Python 复算得到的（`tools/probes/score_test.py`），**不是**在手机上跑出来的。

## 四、顺带修的两处

1. **网易指纹只取前 12 秒**：用户把时长档位调到 15/20 秒时，之前会把整段 PCM 丢给 `NeteaseFingerprint.encode`，指纹窗口跟着变；现在统一截前 12 秒（网易的最低/标准窗口），口径不再漂。
2. **网易最多等 7 秒**：WebView 起不来或网络打摆子时只走酷狗，不把整次识别拖死；超时就当网易没结果，仍按酷狗打分出结果。

## 五、界面

结果卡在专辑下面多一行灰色小字：

## 七、缺口（必须说清）

1. **没有真机、没有模拟器**：这次改的是判定逻辑，不是 UI，静态验证能覆盖"代码路径与文案进包"，**但覆盖不了"手机外放真实录音时两条通道各返回什么"**。张杰那个例子是用构造夹具验证的，不是用真机录到的音频。
2. **网易 recognition 的实际召回未知**：本地留存的真实网易响应里，《晴天》只回了翻唱（王先森、雷米克斯、丹尼尔），没有周杰伦。如果真机上网易也这样，那么"酷狗给翻唱、网易给原唱"这个假设未必稳定成立——打分模型能保证"在有原唱候选时选原唱"，不能凭空造出原唱。
3. **`is_original` 的语义是按一条实测样本推断的**（原唱=1、翻唱=2、无信息=0），酷狗没公开文档；如果它改字段，+45/−30 会失效，但其它维度仍在。
