### v2.1.32 悬浮栏整条可点 + 阻断穿透

**现象**：只有点封面、歌名、歌手名才打开播放页；点到旁边一点，就直接穿过悬浮栏、把后面列表里的歌切掉。

**录屏取证**：12:43 那条 24s 录屏逐秒抽帧（29fps / 704 帧 / 540×1172），全程是「首页 ↔ 播放页」往返：0~2s 首页、3s《外婆》播放页、4~6s 首页、6~9s 又是《外婆》播放页、10s 首页、11s《李候风》播放页、12~14s 首页、15s 播放页、16s 首页、18s 播放页、19~24s 停在首页。其中 17s 那一帧是决定性证据：悬浮栏显示的是《外婆》，可下面「热门音乐」第 02 行《十年》被按下高亮 —— 手指点在悬浮栏上，事件已经落到后面的列表行里去了。另有多次点悬浮栏没进播放页，就是你说的「点了没反应」。

**根因**：悬浮栏是叠加在列表之上的一个 Box，画卷本身只用 drawBehind 铺图，不参与命中测试。v2.1.31 撤掉那层手势通道之后，真正可点的只剩三块：封面 42dp、歌名区（0.26w 起、宽 0.23w）、四个钮（0.50w~0.952w × 0.18~0.82 高度）。悬浮栏剩下的地方 —— 上下山水留白、封面左侧、钮与钮之外的空隙、最右边轴杆 —— 完全没有点击处理，触摸就直接穿透到下层歌曲列表，把列表里落点那一行的歌切了。

**修法**：在悬浮栏最底层铺一层铺满整条的点击层（第一个声明的子元素，也就是最底层），点它任意位置都打开当前这首歌的播放页：

1. 点空白 → 打开当前歌的播放页；点四钮 / 封面 / 歌名时，它们在更上层先命中，行为完全不变，两者互不干扰。
2. 因为现在点击层独占整条，穿透被从源头堵死 —— 悬浮栏上任何一个落点都不会再落到后面的歌曲行。
3. 点击层不设压暗效果（indication = null），画卷视觉保持干净，不会整幅变暗。
4. 对正在播放的这首歌再点悬浮栏，只打开播放页，不会重新取流、不会从头重播（取流入口自带「已在播则直接返回」的判断）。
