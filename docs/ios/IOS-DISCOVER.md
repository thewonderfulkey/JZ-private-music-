## 1 为什么之前"发现页什么都没有"

上一版发现页只有两块**由本地历史派生**的内容：最近播放、猜你喜欢（其实就是最近播放换个标题）。
新用户没有历史，于是：

```
编辑精选 = 3 个写死的静态分类卡（点不开，卡片下手写"随 P1 接入"）
最近播放 = 空 → 整块不渲染
猜你喜欢 = 空态文案（"多听几首，这里会长出来"）
热门音乐 = 一行占位（"随 P1 接入"）
```

表现出来就是"什么都没接 UI"。**根因不是 API 不通，是这一页根本没有数据源**：
四家平台的搜索/取流/封面/歌词都能用，而「歌单 / 榜单」这一层——**2026-11-17 之前的结论是"一家都没有"，
这个结论对酷狗/QQ/网易成立，对酷我不成立**（见 §2.1）。所以 Android 端那套「内置歌单池 + 种子词搜索合并」
被 iOS 照搬了过来，它仍然是「编辑精选 / 猜你喜欢 / 热门音乐」三块的底座。

> ⚠️ 2026-11-17 修订：上面这句"没有一家提供榜单接口"曾写进本文件与 `DiscoverFeed.swift` 的注释里，
> 实测被推翻——酷我有一整套匿名榜单/歌单/歌手接口，**现在它就是热门音乐的数据源**（§2.1），
> 编辑精选那一排仍是原来的 4 张本地池卡。

## 2 三条链路（都是真数据，没有编造）

| 区块 | 数据来源 | 失效时的表现 |
|---|---|---|
| **编辑精选** | 内置池 4 类 × 30 首（[DiscoverCatalog.swift](ios/JZMusicHelper/Models/DiscoverCatalog.swift)，逐字照搬 Android `HomeScreen.kt` v2.1.59）→ 按 UTC 天数滑窗取 20 首；进页面后台把 20 首解析成真实 Song，行内直接有封面/歌手·专辑/平台/时长/收藏 | 没解析出来的行留占位行；解析失败 → 行尾 `exclamationmark.triangle.fill` + 底部状态行「《X》没找到可播放的版本」 |
| **热门音乐** | **① 首选：酷我官方热歌榜**（`kbangserver.kuwo.cn/ksong.s`，匿名、无签名，100 首/日更，模块取前 21）→ **② 兜底：原来那套** 24 个种子词按天取 6 个 → 四平台并发搜索 → `pick` 选 21 首；结果当天缓存进 UserDefaults | 两个来源都拿不到才失败态 + 「重试」；缓存按 `day` 失效（v2 缓存，旧 v1 当天也不复用） |
| **猜你喜欢** | 最近播放 → 抽 3 个歌手（`DiscoverRules.guessKeywords`）→ 搜他们的歌 → 剔掉听过的 → `pick` 取 6 首 | 失败态一行 `StatusLine` + 「重试」；一首都没搜到就换今天的热门补位 |

**没有任何一条走"假数据"**：`DiscoverFeed` 只在真榜/真搜索结果里取，取不出来就显示失败态。
副标题也说实话：用榜单时写「酷我热歌榜 · 每日更新」，回落时写「四平台合并 · 每日更新」。

## 2.1 榜单（酷我官方榜：热门音乐的主数据源）

`热门音乐` 的数据源在第二十轮换成**酷我官方热歌榜**，原来的种子词搜索降级为兜底；样式、页数（21 首 = 3 行 × 7 页）
一律不变，「查看全部」进榜单页看完整 100 首。编辑精选里那张单独的榜单卡已撤掉（老板："把热歌榜换到热门音乐里"）。

| 项 | 值 |
|---|---|
| 榜单目录 | `https://wapi.kuwo.cn/api/pc/bang/list`（36 个叶子榜，本机实测 18 KB / 2.0 s） |
| 榜单歌曲 | `https://kbangserver.kuwo.cn/ksong.s?from=pc&type=bang&id=<mobileId>&pn=0&rn=100`（本机实测 120 KB / 3.5 s） |
| 代码 | `ios/JZMusicHelper/Services/KuwoChart.swift`（解析纯函数） + `Services/DiscoverRules.swift`（`hotModuleSongs`）+ `Views/ChartSongsView.swift`（页面） |
| 匿名性 | 无登录、无签名、无 cookie；`bang/list` 与 `ksong.s` 实测 **https 直连即通**，不需要 ATS 例外 |
| 名次口径 | 模块与榜单页都**保持官方名次**：不重排、不在榜单里做"原版筛选"（`hotModuleSongs` 有断言） |

两个踩过的坑，都写进了 `KuwoChart.swift` 的文件头注释：

1. **两级 id**：目录里 `id`（web，489927）喂给 `ksong.s` 只回 `{}`（2 字节，但 HTTP 200）；
   取歌必须用 `sourceid`（mobile，16）。`Chart` 两个 id 都留着，只有 `mobileId` 上请求。
2. **曲长不在 `duration`**：实测同一批曲 `duration` 是 4 / 1 / 41 / 107 这类值，真曲长在 `song_duration`
   （189 / 272 / …）。用错会直接打穿播放侧的 ±25s 时长闸门（`PlaybackRules.durationToleranceSec`）：
   期望 4s 时真歌被判坏源全网跳歌，反过来 4s 试听片段反而会被当好源。

**榜单曲没有任何封面字段**，所以这一页 100 行的图全靠兜底——顺手把封面链补了：
`CoverResolver` 现在先走**酷我同平台按 rid 取图**（`artistpicserver` 的 `rid_pic`），取不到才跨平台去 QQ 猜。
这条兜底也覆盖了原来那约两成没有 `MVPIC` 的酷我搜索结果（此前全靠 QQ 跨平台兜底）。

`rid_pic` 的响应有三个坑，`CoverResolver.ridPicURL(fromBody:)` 里逐条处理并有断言：

| 坑 | 处理 | 实测 |
|---|---|---|
| 返回的是 `http://` | 统一升 https | iOS 已开 ATS 严格，http 会被系统拦掉 |
| 域名是 `img1.kwcdn.kuwo.cn` | 换成 `img1.kuwo.cn` | 该域**不提供 https**（TLS 直连失败）；同路径在 img1/2/4.kuwo.cn 上 https 200 且字节一致 |
| 个别 rid 返回 `starheads`（歌手头像） | 直接拒收 | 贴到歌曲行上是张冠李戴，比没图更糟 |

**可播性实测**（本轮新增，取 3 个榜各 6 首走现有妖狐酷我通道）：热歌榜 6/6、华语榜 6/6、经典怀旧榜 6/6
全部拿到无损直链——所以榜单页不需要「试听」标记，也没改播放引擎。榜单自带 `payInfo.listen_fragment`
字段（抽取的 10 首里 8 首为 1）在本机链路下不影响取流，暂时只作为解析结果保留，不做 UI 表达。

## 3 挑选口径（与 Android 同口径，全部钉在 CI 断言里）

| 规则 | 为什么 | 代码 |
|---|---|---|
| **只要原版**：`name == coreName(name)` | 榜单里出现「夜曲 (Live)」「夜曲 - DJ版」= 一眼假 | `DiscoverRules.pick` |
| **同曲去重**：按 `coreName` 归并 | 四个平台都返回同一首歌，不去重会连续 4 条一样 | 同上 |
| **同歌手 ≤2 首**、**同歌手不相邻** | 种子词里有 6 个周杰伦，不限制会变成"周杰伦榜" | `pick`（第二遍才放宽相邻，保证凑得满） |
| **核心歌名**：去括号内容、去 Live/DJ/翻唱/伴奏/纯音乐 等后缀、去尾部连接符 | 同一首歌的十几种写法要归成一个 | `DiscoverRules.coreName` |
| **每日轮换**：`rotate(pool, day, take)` | 编辑精选的"每日换一批"，同一天多次打开稳定 | `DiscoverRules.rotate` |

对应断言 22 条：`ios/SelfTest/main.swift` 的 `section("发现页口径…")`。

## 4 已知取舍（都写进代码注释了）

1. **「播放全部」只预热 5 首**：一首一次四平台搜索，20 首要一分多钟，用户会以为卡死。现在凑够 5 首就起播，其余点哪首解析哪首。Android 是"后台并发补队列"，那需要引擎支持队列追加，留下一步。
2. **编辑精选的池子没有 Android 的 DynamicPool**：Android 每天往池子里注入新搜到的歌（上限 2000、近 7 天不重推）。iOS 现在只做日期轮换——内容会重复，但不至于空。
3. **热门音乐 = 榜单优先 + 种子词兜底**（第二十轮改）：真榜拿得到就整块用榜（副标题写「酷我热歌榜 · 每日更新」），
   拿不到就回落到"四平台合并 + 原版优先"（副标题写「四平台合并 · 每日更新」）。两个来源不要混成一个口径：
   一个是平台给的排名，一个是我们自己挑的。**排名顺序一律不做二次筛选**——榜单页与模块都按官方名次显示。
4. **编辑精选歌单页要在进页面时把 20 首解析成真实 Song**（第二十轮起）：池子里只有「歌名 + 歌手」，
   所以封面/专辑/收藏都必须等解析。现在是并发 3 渐进补（解析出一首填一格），代价是这一页
   首屏会有几秒"占位行 → 正式行"的替换过程；换来的是行内有封面、歌手·专辑、平台、时长、收藏。
4. **猜你喜欢的推荐理由**目前只有一句"根据你最近的播放"，没有 Android 的"和你常听的《X》同年代"式文案（那需要 SongProfile 向量计算）。
5. **类别主题色**（`0xF0B45A` 等 4 个）是设计令牌之外唯一的颜色来源，因为类别色属于数据；卡片里没有 AI 海报，用同色渐变块。

## 6 装机要看的 5 件事

1. 打开 App 停在发现页：**编辑精选回到 4 张卡**（华语经典/粤语金曲/影视 OST/欧美热单）；
   下面是热门音乐，副标题应是「酷我热歌榜 · 每日更新」，仍是 3 行一页、7 个圆点。
2. 点热门音乐右侧「查看全部」→ 榜单页：页头「100 首 · 更新 <日期> · 酷我官方榜」+「播放全部」，
   100 行是**统一行样式**（52pt 封面 / 歌名 / 歌手·专辑 / 平台胶囊 / 时长 / 收藏心 / 行首名次），
   **每行都有封面**（榜单没有封面字段，全靠 rid_pic 兜底，这是重点要看的地方）。
3. 点「华语经典」→ 20 首的页面：应先是带占位封面的行，随后逐行换成真封面 + 歌手·专辑 + 收藏心；
   点第 3 首：行尾转圈 → 起来出声（失败则行尾变橙色感叹号 + 底部一行原因）。
4. 点「播放全部」：先显示"正在准备队列 n/5"，然后起播；播放页队列应是 5 首。
5. 播一首听几秒，等它自然播完跳下一首（或手动切歌）：**悬浮栏的封面、歌名、歌手必须同时换**。
   （第二十轮修的 bug：半壶纱播完切到奢香夫人时，悬浮栏封面还停在上一位。）
