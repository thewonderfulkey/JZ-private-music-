## 2 歌词 API：酷我官方 / 酷狗 KRC / QQ QRC

| 链路 | 状态 | 实测结果 |
|---|---|---|
| 酷我官方 `getlyric?musicId=` | ✅ 已验证 | 《晴天》**150 行**（行级时间，无逐字）；接口要求在 `data.lrclist`，`time` 是秒 |
| 酷狗 KRC（complexsearch → lyric search → download → 解密） | ✅ 已验证，3/3 | 《晴天》63 行/首行逐字 14；《夜曲》84 行/6；《稻香》53 行/8 |
| QQ QRC（musicu.fcg → GetPlayLyricInfo → 解密） | ✅ 链已跑通一次（**接口间歇限流**） | 《稻香》**48 行 / 首行逐字 14**，`qrc_t=1618906414` 生效；但随后 8+ 次重试全部 `request.code=2001`（空候选） |
| KRC/QRC 解密算法 | ✅ 已验证 | KRC：真实 4192 字节密文 → 8405 字符/63 行；QRC：**合成样本往返 + 6 组 3DES 向量双向**（Python 独立实现生成）；另有真实 QRC 一次成功解出 48 行 |
| 候选评分（选对歌） | ✅ 已验证 | 11 组真实歌名/歌手与 Python 参考实现逐条对齐（含"晴天 vs 晴天 (Live)""龙文 vs 合唱版"） |
| 取词优先级 + 4h 缓存 + 并发去重 | ✅ 逻辑已验证 | 酷我优先 → LDDC；actor 缓存；CI 无网络，靠代码审查 + 编译 |
| 酷狗签名 | ✅ 已验证 | SearchSong / Lyric 两条 query 与 Python 参考实现**逐字节一致**（固定 mid/clienttime） |

**"命中率"要知道的两件事**：
1. 酷狗 KRC 这三首是 3/3；样本小，但都是正常流行歌（不是冷门曲）。
2. QQ 那条**不是逻辑问题，是限流**：同一台机器同一分钟里，第一次成功、后面全 2001。真机上换网络/换 IP 大概率不复现。

> 🟡 **QQ 取词链的稳定性未验证**（只能真机验）：需要装包后在设备上试几首，看 2001 出现频率。
> 解密算法本身不依赖这个：真实 QRC 已成功解出过一次，且合成样本 + 向量把算法钉住了。

## 3 封面 API：字段解析 / 兜底

### 3.1 各平台封面字段（真实取一次，Range 0-1）

| 平台 | 字段 | 实测 |
|---|---|---|
| QQ | `albummid` → `y.gtimg.cn/music/photo_new/T002R300x300M000{mid}.jpg` | ✅ HTTP 206 `image/jpeg`，字节可读 |
| 网易 | `/api/search/get` 无 picUrl → `/api/song/detail?ids=[…]` 批量补 `album.picUrl` | ✅ HTTP 206 `image/jpg`，字节可读 |
| 酷狗 | `trans_param.union_cover`（`{size}`→500，http→https） | ✅ HTTP 206 `image/jpeg`，字节可读 |
| 酷我 | `MVPIC` → `img1.kuwo.cn/wmvpic/…` | ✅ 字段存在时可取；**实测约两成结果没有 MVPIC** → 必须兜底 |

### 3.2 兜底（本轮补的缺口）

原来 iOS **完全没有**这部分（Android 有 `CoverResolver.kt`）。现已移植 [CoverResolver.swift](ios/JZMusicHelper/Services/CoverResolver.swift)：

- 规则：**只兜没封面的歌**；用「歌名 + 歌手」去 QQ 搜 10 条，要求**歌名完全相等 + 歌手任一片段相等**才采用；匹配不上返回 nil（宁可用占位图，也不张冠李戴）
- 旧封面判死：酷狗 `imgessl` 路径已被 CDN 软失败（HTTP 200 + 固定黑胶图）→ 当作没有，强制兜底
- 三条工程约束（照搬 Android）：并发上限 3、同 key 进行中去重、内存 + UserDefaults 缓存（最多 300 条）

**实测效果**：10 条无封面样本，**兜底成功 7 条**（3 条失败是 QQ 确实没有严格同名同歌手的条目，属正确行为）。

> 🟡 兜底的 Swift 运行时（真机加载、缓存命中）未验证；规则本身有 11 条断言（`isStrictMatch` / `isLegacyDeadCover`）。

## 5 只能真机验的项（不在本机能力范围）

1. **QQ 取词稳定性**：本机 IP 被间歇限流（`request.code=2001`），真机/换网络要复测。
2. **设备侧网络与证书**：酷狗旧域名证书不匹配那类问题在 iOS 上已通过换宿主 + 严格 ATS 规避，但真实设备（尤其蜂窝网络 + 运营商劫持）行为只能装机看。
3. **`URLSession.bytes` 的 Range 探测**：iOS 在部分 CDN 上会忽略 Range 直接回 200，Swift 已按 Content-Length 兜底并只读 16 字节，但真实命中率要装机看。
4. **AsyncImage 加载与缓存**：iOS 侧没有第三方图片库，缓存行为（含重试）只能真机观察。
5. **后台播放**：本轮补了 `UIBackgroundModes=audio`，之前缺失（没有它进后台就停）。是否真能后台续播只能装机验。

## 6 本轮顺手补的两个洞

2. **`NSMicrophoneUsageDescription` 缺失** → 识曲（P3）会被系统直接拒。已补文案（设计稿 §3.8 定稿版本）。
